# Current Repo Questions

Date: 2026-06-01

Purpose: questions to clarify before using the current results as evidence for MTUP.

- **Question:** Which code version generated the current `results/**/scores.json` files?
  **Note:** Current source code and some saved outputs may not fully match, so the scores may not be reproducible from the checked-in code.

- **Question:** Were each method's `*_full.txt` and `*_pred.txt` files generated by the same inference run?
  **Note:** Extraction correctness depends on output headers; if full outputs and predictions come from different scripts, debugging and reruns become unreliable.

- **Question:** What exact commands generated formatted data, checkpoints, predictions, and scores?
  **Note:** The current repo does not preserve full run history, so command history is needed to reproduce the results.

- **Question:** Did the main runs use a fixed dev split and validation-Smatch checkpoint selection?
  **Note:** The original experimental design required this for defensible model selection and to avoid tuning decisions based on the public test set.

- **Question:** Was Vietnamese `legacy` no-var mode intentional for B2 and old MTUP variants?
  **Note:** `legacy` mode may leave variable-like references, making the no-var baseline stronger or less clean than intended.

- **Question:** Did English and other cross-lingual results use all three seeds?
  **Note:** The protocol requires mean and standard deviation over three seeds; single-seed cross-lingual results are weaker evidence.

- **Question:** Were any predictions manually edited, regenerated, or produced by older scripts?
  **Note:** Manual edits or script drift would affect trust in the reported scores and make ablations hard to compare.

- **Question:** What exact Python, package, CUDA, and GPU environment was used?
  **Note:** Dependencies are not tracked in the repo, and small library/version differences can change training or inference behavior.

- **Question:** Did the detailed Vietnamese system prompt include rules derived from public test examples?
  **Note:** Test-derived prompt rules would create leakage risk and weaken claims about generalization.

- **Question:** Are the detailed system-prompt rules meant to generalize beyond this dataset?
  **Note:** Highly dataset-specific rules may inflate current scores while making the paper claim less general.
